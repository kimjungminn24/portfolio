## 문제가 생긴 이유

기존 통계 API는 사용자가 요청할 때마다 전체 데이터를 조회하고 통계를 계산하는 구조였습니다.

데이터가 쌓일수록 계산량이 늘어났고, 메인 페이지에 트래픽이 몰리는 경우 평균 응답 시간이 14,755ms까지 발생했습니다.

통계 데이터가 매 요청마다 실시간으로 계산되어야 하는 것은 아니었기 때문에, 계산 시점과 조회 시점을 분리하기로 했습니다.

## 개선 과정

1. `@Scheduled`를 사용해 통계 데이터를 주기적으로 집계하도록 변경했습니다.
2. 여러 인스턴스에서 같은 집계 작업이 중복 실행되지 않도록 ShedLock을 적용했습니다.
3. 집계 결과를 별도 테이블에 저장하고 API에서는 저장된 결과를 조회하도록 변경했습니다.
4. 집계 로직에 `parallelStream()`을 적용해 병렬 처리도 함께 시도했습니다.

## 결과

| 항목 | 개선 전 | 개선 후 |
| --- | ---: | ---: |
| 평균 응답 시간 | 14,755ms | 1,011ms |

요청이 들어올 때마다 수행하던 계산을 별도 작업으로 분리하면서 평균 응답 시간을 약 14.6배 줄였습니다.

통계처럼 실시간성이 상대적으로 낮은 데이터는 조회 시점에 모든 계산을 수행하기보다 미리 집계해 두는 방식이 효과적이라는 점을 확인했습니다.
