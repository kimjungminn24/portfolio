## 고민

모델이 그림 하나를 그리는 동안 캔버스를 읽고 픽셀을 보내는 걸 수십 번 반복해요. 여기서 토큰을 덜 쓰면 한 대화에서 더 오래 그릴 수 있을 것 같아서, 주고받는 데이터를 줄여 보기로 했어요.

## 해결

### 도형은 숫자 몇 개로 그리기

처음에는 모델이 칠할 픽셀 좌표를 전부 보내야 했어요. 반지름 20인 원 하나만 채워도 좌표가 1,257개였어요. 그래서 직선이랑 사각형은 꼭짓점 두 개, 원은 중심과 반지름만 받고 나머지 픽셀은 서버에서 채우게 바꿨어요.

![도형 도구 비교](assets/pixel-duet/shapes.svg)

### 캔버스 읽기에 RLE 압축 적용

캔버스를 읽어 줄 때는 RLE(Run-Length Encoding) 압축을 넣었어요. 같은 색이 이어지면 `4*16` 처럼 색과 개수로 묶고, 똑같은 줄이 반복되면 `y3-9:` 처럼 줄 범위로 접어요. 무늬가 복잡하면 압축한 게 더 길어지기도 해서, 그럴 땐 원래 형태로 보내요.

![RLE 압축 예시](assets/pixel-duet/rle.svg)

## 성과

Anthropic 공개 토크나이저(`@anthropic-ai/tokenizer`)로 전후 토큰 수를 재 봤어요.

| 항목 | 이전 | 이후 |
| --- | ---: | ---: |
| 채운 원 하나 그리기 (토큰) | 10,064 | 25 |
| 128×128 개구리 `read_pixels` 응답 (글자) | 16,512자 | 3,760자 |
| 128×128 개구리 `read_pixels` 응답 (토큰) | 2,651 | 2,548 |

## 배운 점

RLE 로 글자 수가 4분의 1이 됐으니 토큰도 그만큼 줄었을 줄 알았는데, 막상 재 보니 4% 정도밖에 안 줄었어요. 토크나이저가 `0000…` 같은 반복은 원래 한 덩어리로 묶고 있었고, `0*8 1*4` 처럼 숫자랑 기호가 섞이면 오히려 토큰이 잘게 쪼개졌어요.

도형 도구는 보내는 정보 자체가 줄어드니까 토큰도 그대로 줄었어요. 토큰을 아끼고 싶으면 짧게 적는 방법보다 애초에 보낼 걸 줄이는 쪽을 먼저 봐야겠다고 생각했어요.

측정에 쓴 토크나이저는 이전 Claude 모델용이라 지금 모델에서는 숫자가 조금 다를 수 있어요.
