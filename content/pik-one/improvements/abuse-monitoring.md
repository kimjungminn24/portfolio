## 문제가 생긴 이유

외부에서 서버에 대량의 요청이 들어오면서 실제 서비스가 다운되는 상황이 발생했습니다.

Nginx 로그를 확인해 보니 일반적인 서비스 요청뿐 아니라 `.env`, `.git` 등 민감한 파일을 탐색하는 요청도 섞여 있었습니다.

서비스를 다시 실행하는 것만으로는 같은 문제가 반복될 수 있다고 판단해 요청 차단과 모니터링 환경을 함께 구성했습니다.

## 요청 차단

- Badbot-blocker와 Nginx rate limiting을 적용해 비정상적인 요청을 제한했습니다.
- Fail2ban으로 반복적인 악성 요청이 발생한 IP를 로그 기반으로 차단했습니다.
- Nginx 서버 버전 노출을 제한하고 `.env`, `.git` 등 숨김 파일에 대한 외부 접근을 차단했습니다.

## 모니터링 구성

서버 자원이 제한적인 프리티어 환경이기 때문에 별도 모니터링 서버를 운영하는 대신 Promtail과 Grafana Cloud를 활용했습니다.

- Promtail로 서버 로그 수집
- Grafana Cloud에서 로그 조회 및 검색
- Slack 알림으로 서버 상태와 보안 이벤트 확인

Grafana에서는 검색 API 로그를 데코 유형별로 집계해 어떤 유형의 검색이 많이 발생하는지도 확인할 수 있도록 구성했습니다.

```
sum by(type) (
  count_over_time(
    {job="nginx"} |= "/api/decors/search"
    | regexp "type=(?P<type>[^& ]+)" [24h]
  )
)
```

## 결과

문제가 발생한 이후 요청 차단 규칙과 로그 수집 환경을 갖추었습니다. 이전에는 서버에 문제가 생긴 뒤에야 원인을 확인할 수 있었지만, 이제는 로그와 알림을 통해 서버 상태와 비정상적인 요청을 확인할 수 있습니다.
